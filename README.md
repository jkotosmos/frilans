# Артель — биржа фриланса

Полноценный маркетплейс фриланс-услуг в духе Kwork/FL.ru: каталог услуг с пакетами
и ценами, профили исполнителей, заказы с жизненным циклом (оплата → работа → сдача →
приёмка/отзыв), встроенные сообщения между заказчиком и исполнителем, личный кабинет
и панель управления своими услугами.

Это не макет — весь описанный ниже поток работает по-настоящему поверх реальной базы
данных: регистрация, аутентификация, создание услуг, оформление заказов, переписка,
отзывы. Единственное, что явно смоделировано, а не подключено к реальному провайдеру —
это оплата (см. раздел «Что не входит» ниже).

Тот же код работает и как **Telegram Mini App** — вход через Telegram без пароля,
нижний таб-бар вместо сайтовой шапки, диплинки на конкретные услуги. Подробности и
настройка бота — в [`TELEGRAM.md`](./TELEGRAM.md).

## Стек

- **Next.js 14** (App Router) + **TypeScript**
- **Tailwind CSS** — авторская дизайн-система («Артель»: тёплая палитра ink/cream/rust/pine,
  контраст serif-заголовков и sans-текста), без стоковых фото — обложки услуг и аватары
  генерируются детерминированно по seed прямо в SVG
- **Prisma** + SQLite для разработки (схема без проблем переносится на PostgreSQL — см. ниже)
- **NextAuth.js** (Credentials + JWT-сессии, пароли на bcrypt)
- **Zod** — валидация всех входных данных на сервере
- **Server Actions** — вся запись данных идёт через них, без отдельного REST/GraphQL слоя

## Быстрый старт

```bash
npm install
cp .env.example .env        # затем сгенерируйте свой NEXTAUTH_SECRET (см. ниже)
npm run db:push             # создать SQLite-схему
npm run db:seed             # заполнить демо-данными
npm run dev
```

Откройте http://localhost:3000.

Сгенерировать секрет для `.env`:

```bash
openssl rand -base64 32
```

### Полезные команды

| Команда | Назначение |
|---|---|
| `npm run dev` | Запуск в режиме разработки |
| `npm run build` | Продакшен-сборка (`prisma generate` + `next build`) |
| `npm run start` | Запуск продакшен-сборки |
| `npm run lint` / `npm run typecheck` | Линт и проверка типов |
| `npm run db:push` | Синхронизировать SQLite-схему |
| `npm run db:seed` | Засеять демо-данными |
| `npm run db:reset` | Полный сброс схемы + повторный сид |

## Архитектура

```
src/
  app/                    # страницы (App Router) и layout'ы
    (marketing pages)     # /, /about, /how-it-works, /safety, /legal/*
    services/             # каталог + карточка услуги
    freelancers/          # каталог исполнителей + профиль
    login, register/      # аутентификация
    dashboard/             # приватный личный кабинет (защищён middleware)
    api/auth/[...nextauth] # NextAuth route handler
  components/
    ui/                   # кнопки, карточки, инпуты, рейтинг, генератор обложек/аватаров
    layout/                # шапка, подвал, поиск, меню категорий
    catalog/               # карточки услуг/исполнителей, панель заказа
    dashboard/             # сайдбар, статус заказа, формы кабинета
  lib/
    actions/               # server actions — единственный путь записи в БД
    validations/           # zod-схемы для каждого действия
    queries/                # переиспользуемые выборки для страниц
    auth.ts, session.ts     # конфигурация NextAuth и хелперы сессии
    rate-limit.ts           # простой лимитер запросов (см. SECURITY.md)
  middleware.ts             # security-заголовки, CSP-nonce, защита /dashboard
prisma/
  schema.prisma             # модель данных
  seed.ts                   # генератор демо-данных
```

### Модель данных (кратко)

`User` (роль `CLIENT`/`FREELANCER`/`ADMIN`) → `Service` (категория, статус) → `Package`
(до 3 тарифов: Базовый/Стандарт/Премиум) → `Order` (статусная машина: ожидание оплаты →
в работе → сдан → принят/доработка/спор) → `Review`. Отдельно — `Conversation`/`Message`
для переписки и `Favorite` для избранного. Подробности — в `prisma/schema.prisma`,
там же пояснение, почему enum-поля хранятся как `String` (SQLite не поддерживает enum;
единственный источник истины по допустимым значениям — zod-схемы в `lib/validations`).

### Дизайн

Название и палитра выбраны осознанно, чтобы не быть похожими на типовой
«AI-сгенерированный SaaS» с фиолетовым градиентом: тёплый кремовый фон, чернильный
текст, терракотовый акцент (rust) и хвойный (pine) — образ артели мастеров, а не
абстрактного стартапа. Вместо стоковых фотографий — сгенерированные по seed обложки
(`components/ui/generated-cover.tsx`) и аватары-инициалы (`components/ui/avatar.tsx`):
это не заглушка «пока нет своих фото», а осознанное визуальное решение, которое к тому
же не тянет внешние ассеты и не требует загрузки файлов.

## Что не входит (и что нужно сделать перед реальным запуском)

Это учебный, но полнофункциональный проект. Явно смоделировано и требует доработки перед
продакшеном:

- **Оплата.** Кнопка «Оплатить» переводит заказ в статус «в работе» без реального списания
  средств — это симуляция резервирования оплаты у эскроу-сервиса. Перед реальным запуском
  нужно подключить платёжного провайдера (например, ЮKassa/Stripe) и провести резервирование/
  выплату через него.
- **Верификация исполнителей.** Флаг `isVerified` — демо-данные, реального процесса проверки
  документов нет.
- **Rate limiting.** Лимитер в `lib/rate-limit.ts` — in-memory, работает только в рамках одного
  процесса/инстанса. Для горизонтального масштабирования замените на общий стор (Redis/Upstash).
- **Загрузка файлов.** Не реализована намеренно (см. `SECURITY.md`) — вложения к заказам не
  поддерживаются, только текстовые требования и сообщения.
- **Email.** Уведомления не отправляются — вся коммуникация только в интерфейсе.

Подробный разбор модели угроз и мер защиты — в [`SECURITY.md`](./SECURITY.md).

## Деплой

Пошаговая инструкция (Vercel + GitHub — рекомендуемый путь, плюс Docker для
self-hosted) — в [`DEPLOYMENT.md`](./DEPLOYMENT.md). Коротко: смените SQLite на
PostgreSQL, сгенерируйте новый `NEXTAUTH_SECRET`, задайте `NEXTAUTH_URL` на
реальный HTTPS-домен — остальное покрывает CI (`.github/workflows/ci.yml`) и,
при выборе self-hosted пути, автосборка Docker-образа
(`.github/workflows/docker-publish.yml`).
