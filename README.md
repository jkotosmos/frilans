# Артель — биржа фриланса

Маркетплейс фриланс-услуг в духе Kwork/FL.ru: каталог услуг с пакетами и ценами,
профили исполнителей, заказы с жизненным циклом (оплата → работа → сдача →
приёмка/отзыв), встроенные сообщения между заказчиком и исполнителем, личный
кабинет и панель управления своими услугами.

## Текущий режим: статическое демо на GitHub Pages

Это пробный запуск — сайт собирается как **статический экспорт** (`output:
"export"`) и раздаётся GitHub Pages, без сервера и без базы данных. Практическое
следствие:

- Каталог, профили, отзывы, личный кабинет — реальные данные, но это
  **снимок** (`src/data/seed-data.json`), а не живая база. Обновляется только
  пересборкой.
- Личный кабинет открыт **без входа**: вместо настоящей сессии весь сайт
  рендерится от лица одного фиксированного демо-пользователя
  (`src/lib/static-data.ts` → `getDemoUser()`) — так `/dashboard` можно
  посмотреть, не изображая форму логина, которой некуда было бы отправлять
  данные.
- Формы и кнопки, которые в динамической версии писали в базу (вход,
  регистрация, оформление заказа, сообщения, отзывы, редактирование профиля/
  услуги) — **видны и кликабельны, но не сохраняют** ничего: вместо запроса
  показывается тост «демо-версия, без сервера» (`src/lib/demo-actions.ts`).
  Это осознанное решение по прямому запросу, а не недоделанная фича.

Полноценная версия с реальной регистрацией, PostgreSQL и Server Actions уже
была реализована и полностью рабочая — она осталась в истории git (см.
`DEPLOYMENT.md` → «Полная динамическая версия», там же как её поднять заново).

Тот же UI-шелл работает и как **Telegram Mini App** (нижний таб-бар, диплинки,
определение контекста) — подробности в [`TELEGRAM.md`](./TELEGRAM.md); в
статическом режиме вход через Telegram, как и обычный вход, — витрина, не
рабочий поток.

## Стек

- **Next.js 14** (App Router, static export) + **TypeScript**
- **Tailwind CSS** — авторская дизайн-система («Артель»: тёплая палитра ink/cream/rust/pine,
  контраст serif-заголовков и sans-текста), без стоковых фото — обложки услуг и аватары
  генерируются детерминированно по seed прямо в SVG
- **Данные** — статический JSON-снимок (`src/data/seed-data.json`), читается
  синхронными функциями в `src/lib/static-data.ts`; никакого обращения к БД в
  рантайме нет
- **Zod** — по-прежнему разбирает query-параметры каталога на клиенте
  (`lib/validations/service.ts`); серверная валидация форм записи — часть
  динамической версии, см. git-историю и `SECURITY.md`

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:3000 — база данных не нужна, `.env` не требуется.

### Демо-доступ

Никакого входа не требуется — личный кабинет открыт сразу от имени демо-пользователя
`ilya.severov@artel.demo` (исполнитель). Полный список данных — в
`src/data/seed-data.json`, сценарий генерации — `scripts/export-static-data.ts`.

### Полезные команды

| Команда | Назначение |
|---|---|
| `npm run dev` | Запуск в режиме разработки |
| `npm run build` | Статическая сборка (`next build` → каталог `out/`) |
| `npm run start` | Запуск последней собранной версии (`next start`, для локальной проверки) |
| `npm run lint` / `npm run typecheck` | Линт и проверка типов |

## Архитектура

```
src/
  app/                    # страницы (App Router) и layout'ы
    (marketing pages)     # /, /about, /how-it-works, /safety, /legal/*
    services/             # каталог + карточка услуги
    freelancers/          # каталог исполнителей + профиль
    login, register/      # формы входа — видны, но не отправляют данные
    dashboard/             # личный кабинет (открыт всегда, демо-пользователь)
  components/
    ui/                   # кнопки, карточки, инпуты, рейтинг, генератор обложек/аватаров
    layout/                # шапка, подвал, поиск, меню категорий
    catalog/               # карточки услуг/исполнителей, панель заказа
    dashboard/             # сайдбар, статус заказа, формы кабинета
    demo/                  # DemoSessionProvider — фиксированная "сессия" вместо NextAuth
  lib/
    static-data.ts          # вся выборка данных: читает seed-data.json синхронно
    demo-actions.ts          # demoAction() — заглушка вместо server actions с тостом
    session.ts               # getCurrentUser()/requireUser() поверх getDemoUser()
    order-transitions.ts     # состояния заказа (используется как справочные данные)
    validations/              # zod-схемы; сейчас в деле только фильтры каталога
  data/
    seed-data.json            # снимок данных: категории, услуги, пользователи, заказы...
scripts/
  export-static-data.ts       # выгружает Prisma → seed-data.json (нужен реальный Postgres)
next.config.mjs               # output: "export", basePath "/frilans" (см. DEPLOYMENT.md)
.github/workflows/
  deploy-pages.yml             # сборка + публикация в ветку gh-pages при каждом push в main
  ci.yml                       # typecheck + lint + build на каждый push/PR
```

### Модель данных (кратко)

`User` (роль `CLIENT`/`FREELANCER`) → `Service` (категория, статус) → `Package`
(до 3 тарифов: Базовый/Стандарт/Премиум) → `Order` (статусная машина: ожидание оплаты →
в работе → сдан → принят/доработка/спор) → `Review`. Отдельно — `Conversation`/`Message`
для переписки и `Favorite` для избранного. Форма данных — как в исходной Prisma-схеме
(сохранена в git-истории), просто источник теперь JSON-снимок, а не живая таблица.

### Дизайн

Название и палитра выбраны осознанно, чтобы не быть похожими на типовой
«AI-сгенерированный SaaS» с фиолетовым градиентом: тёплый кремовый фон, чернильный
текст, терракотовый акцент (rust) и хвойный (pine) — образ артели мастеров, а не
абстрактного стартапа. Вместо стоковых фотографий — сгенерированные по seed обложки
(`components/ui/generated-cover.tsx`) и аватары-инициалы (`components/ui/avatar.tsx`):
это не заглушка «пока нет своих фото», а осознанное визуальное решение, которое к тому
же не тянет внешние ассеты и не требует загрузки файлов.

## Что не входит в статическое демо

Помимо очевидного «ничего не сохраняется» (см. выше), в статическом режиме
дополнительно не работает то, что физически требует сервера: платежи (были
смоделированы и в динамической версии — см. `SECURITY.md`), rate limiting,
серверная валидация форм, отправка email, реальная проверка подписи Telegram
`initData`. Все эти механизмы **реализованы** в динамической версии и остались
в git-истории — «Что не входит» в изначальном, полнофункциональном смысле
разобрано в [`SECURITY.md`](./SECURITY.md), который описывает именно её.
