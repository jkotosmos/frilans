# Артель как Telegram Mini App

> **Текущий статус:** сайт сейчас — статический экспорт без сервера (см.
> `README.md` → «Текущий режим»), поэтому реального входа через Telegram
> сейчас нет: `telegram-auto-login.tsx` и серверная проверка `initData`
> (`lib/telegram-auth.ts`) были частью динамической версии и остались в
> git-истории вместе с ней (см. `DEPLOYMENT.md`). Всё, что описано ниже про
> UI-обвязку (таб-бар, кнопка «назад», диплинки, определение контекста) —
> работает и сейчас; раздел «Настройка бота» и всё про `initData`/
> `TELEGRAM_BOT_TOKEN` относится к динамической версии.

Этот сайт — один и тот же Next.js-проект для двух сценариев одновременно:
обычный сайт в браузере и Telegram Mini App внутри бота. Ничего не дублируется —
приложение на клиенте определяет, что оно открыто внутри Telegram, и меняет
только «обвязку» (шапку/подвал → нижний таб-бар, вход по паролю → автологин).

## Что изменилось технически

- **SDK.** `telegram-web-app.js` подключается в `app/layout.tsx` через `next/script`
  (`beforeInteractive`, с CSP-nonce). Вне Telegram скрипт просто ничего не делает.
- **Определение контекста максимально рано.** Отдельный инлайновый скрипт, идущий
  раньше SDK и не зависящий от него, проверяет `location.hash`/`location.search` на
  `tgWebAppData` (именно так Telegram передаёт данные при открытии Mini App — через URL,
  а не только через SDK) и ставит `<html data-telegram="1">`. На этом атрибуте построены
  чистые CSS-правила в `globals.css` (`.telegram-hide`, `.telegram-only`). Это самый
  ранний хук, который даёт App Router — по замерам, ~50 мс после DOMContentLoaded в
  продакшен-сборке, а не буквально «до первой отрисовки» (Next.js обрабатывает
  `beforeInteractive`-скрипты через очередь в своём рантайме, а не как классический
  блокирующий `<script>`). Короткое окно с «неправильной» шапкой теоретически возможно,
  но практически незаметно.
- **Навигация.** `components/telegram/mini-app-tab-bar.tsx` — нижний таб-бар
  (Главная/Каталог/Мастера/Кабинет), показывается только внутри Telegram.
  `components/telegram/telegram-back-button.tsx` управляет нативной кнопкой
  «назад» Telegram вместо браузерного «назад», которого в Mini App нет.
- **Вход.** В динамической версии `components/telegram/telegram-auto-login.tsx`
  при первом заходе внутри Telegram сам вызывал `signIn("telegram", { initData })`
  — без формы, без пароля. В текущей статической сборке этого компонента нет:
  личный кабинет и так открыт всегда, от имени фиксированного демо-пользователя
  (см. `README.md`).
- **Диплинки.** `startapp=svc-<slug>` открывает конкретную услугу,
  `startapp=fl-<id>` — профиль исполнителя (см. «Диплинки» ниже).
- **CSP / фреймы.** `middleware.ts`: `frame-ancestors` теперь разрешает
  `web.telegram.org` (и веб-клиенты Telegram) — иначе Telegram Web попросту не
  смог бы встроить сайт в свой iframe. `X-Frame-Options: DENY` убран (он не умеет
  «разрешить конкретный домен», только всё или ничего, и конфликтовал бы с
  `frame-ancestors`).

## Настройка бота

1. Напишите **@BotFather** в Telegram, `/newbot`, задайте имя — получите токен вида
   `123456789:AAgH...`.
2. Положите его в `.env` как `TELEGRAM_BOT_TOKEN`. Без этой переменной сайт работает
   как обычно, просто автологин внутри Telegram будет показывать ошибку "Вход через
   Telegram временно недоступен" — это осознанный fail-closed, а не баг.
3. Задеплойте сайт на настоящий HTTPS-домен — Telegram **не примет** `http://localhost`
   ни в каком виде. Для быстрой локальной проверки подойдёт временный туннель
   (`cloudflared tunnel --url http://localhost:3000` или ngrok), для постоянной
   работы — Vercel/любой хостинг с HTTPS. Не забудьте выставить там же
   `NEXTAUTH_URL` на этот домен.
4. В **@BotFather**: `/mybots` → выберите бота → **Bot Settings** → **Menu Button** →
   укажите URL вашего сайта. Либо `/newapp`, если хотите отдельное Mini App
   (в дополнение к обычному боту), с тем же URL.
5. Откройте бота в Telegram и нажмите кнопку меню — должен открыться сайт,
   автоматически залогинив вас новым аккаунтом с ролью «заказчик».

## Диплинки

Ссылка вида:

```
https://t.me/<ИмяБота>/<app_short_name>?startapp=svc-razrabotayu-sayt-vizitku-na-next-js
```

откроет Mini App сразу на карточке этой услуги. `fl-<id>` — аналогично для профиля
исполнителя. Значение `startapp` Telegram ограничивает символами `[A-Za-z0-9_-]`,
поэтому используется префиксная схема, а не сырой путь.

## Ограничения и что доделать для реального запуска

- Роль новых Telegram-аккаунтов всегда `CLIENT` — переключение на «исполнителя»
  пока доступно только через обычную регистрацию по email. Несложно добавить кнопку
  «стать исполнителем» в `/dashboard/settings`, если понадобится.
- У Telegram-аккаунтов нет пароля (генерируется случайный, неиспользуемый хэш) —
  соответственно, вход по email/паролю для них недоступен, пока пользователь сам не
  задаст пароль (такой формы сейчас нет, это следующий шаг, а не ограничение архитектуры).
- Проверка подписи `initData` (`lib/telegram-auth.ts`) — по официальному алгоритму
  Telegram, HMAC-SHA256 с `TELEGRAM_BOT_TOKEN` как секретом, с проверкой `auth_date`
  (не старше 24 часов, защита от повторного использования утёкшей ссылки). Секрет
  бота держите так же, как `NEXTAUTH_SECRET` — не в git, не в клиентском коде.
